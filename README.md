# maniax

アニメ作品のリバイバル上映・舞台挨拶・原画展・ライブ・グッズ情報を定期的に集めて、
メール / Google カレンダー / スマホ通知に流すウォッチャー。

**GUI（スマホ可）**: <https://claude.ai/code/artifact/de9706cf-f912-4d45-ac25-efa06579b455>
— 予定の一覧、月カレンダー、監視リストの追加・削除。

「気づいたときには上映が終わっていた」を防ぐのが目的なので、
**通知しすぎないこと**を優先している。ウォッチリストに載っていない作品は
既定では通知しないし、日程が既に終わったイベントも落とす。

それ以上に**誤った日程を出さないこと**を優先する。裏の取れない日付は
出さず、「日程未確認」として理由とともに残す。詳細は
[COLLECTION_RULES.md](COLLECTION_RULES.md)。

## 動く仕組み

Routine（定期トリガー）が毎回まっさらなクラウドセッションを起動する。
巡回は 2 本立て。

| 巡回 | 頻度 | 役割 | 手順書 |
|---|---|---|---|
| 全件 | 毎朝 8:00 | ウォッチリスト全部を検索し直す | [ROUTINE_PROMPT.md](ROUTINE_PROMPT.md) |
| 差分 | 毎時 0 分（8 時台を除く） | GUI で追加された分と、再検索ボタンの予約だけを拾う | [ROUTINE_INCREMENTAL.md](ROUTINE_INCREMENTAL.md) |

差分巡回は、やることがなければ DB を読むだけで即終了する。
1 日 23 回動くので、空振りを安くするのが前提の設計になっている。

8 時台に差分巡回を動かさないのは、全件巡回と同時刻になると
2 つのセッションが `state/seen.json` を同時に push して衝突するため。
その時間帯は全件巡回が兼ねる。

なお、実際の発火はスケジューラの都合で指定時刻より少し遅れる
（毎時のものは数十秒程度、日次のものは最大 15 分程度）。

```
        GUI（Artifact）
     ┌──── watchlist ────┐                    ┌──── events ────┐
     │  作品・監督の登録  │                    │   予定・カレンダー │
     └─────────┬─────────┘                    └────────▲────────┘
               │ read_db                               │ write_db
               ▼                                       │
        aew.sync from-db ──> aew.sources ──> 検索クエリ  │
                                                │       │
                                                ▼       │
                                    WebSearch（セッションが実行）
                                                │       │
                                                ▼ candidates.json
                                    aew.ingest ──> digest.json ──┤
                                                │                 │
                                                │                 └──> メール / カレンダー / Push
                                                ▼
                                    state/seen.json（git で永続化）
```

コンテナは実行のたびに消えるので、状態は 2 か所に外出ししている。
**ウォッチリストと表示用のイベント**は Artifact のデータベース（GUI が読み書きする正）、
**「通知済み」の重複判定**は `state/seen.json` を git で持ち回る。
`watchlist.json` は DB のバックアップ兼、DB が読めなかったときの代替。

## ウォッチリストを変える

**通常は GUI から**。「監視リスト」タブで作品・人物を追加／削除する。
リポジトリを触る必要はない。

追加した項目には `searched: false` が入り、GUI 上では「未検索」と表示される。
差分巡回がこれを見て、翌朝を待たずにその項目だけを検索する（最大 1 時間待ち）。
検索が済むと印が消える。

すでに登録済みの作品をもう一度引き直したいときは、ページ上部の
**「今すぐ再検索」**ボタンを押す。`control/rescan` に予約が立ち、
次の差分巡回が全件を引き直す。ページから直接検索を走らせることはできない
（巡回はサーバ側のスケジュールで動くため）ので、あくまで予約になる。

`watchlist.json` を直接編集して push しても動く（DB が読めなかったときの
代替として使われる）。書式は次のとおり。

```json
{
  "works":  [{ "title": "伝説巨神イデオン", "aliases": ["イデオン"] }],
  "people": [{ "name": "富野由悠季", "role": "監督", "aliases": ["富野喜幸", "井荻麟"] }]
}
```

`aliases` は略称・旧名義を入れておくと取りこぼしが減る。
人名は 3 文字未満だと誤爆しやすいので照合対象から外している。

### settings

| キー | 既定 | 意味 |
|---|---|---|
| `categories` | 5種すべて | 通知する種別（リバイバル / 上映イベント / 展示 / ライブ / グッズ） |
| `include_unmatched` | `false` | ウォッチリスト外のイベントも通知するか |
| `drop_past_events` | `true` | 終了済みのイベントを落とすか |
| `max_queries` | `60` | 1 回の実行で投げる検索クエリの上限 |

作品数 × クエリテンプレート数で件数が増えるため、`aew.sources` は
テンプレート単位のラウンドロビンで並べる。上限で打ち切っても、
特定の作品だけ完全に無視されることはない。

作品を増やすときは `max_queries` も一緒に上げること。
1 作品あたり 3 本使うので、目安は「作品数 × 3 + 人物数 × 2」。
上限に当たると後ろのテンプレート（展示・ライブ系）から落ちていく。

## 情報源

| 種別 | 中身 | 現状 |
|---|---|---|
| WebSearch | 作品名・人物名からの検索、劇場・企画からの検索 | **稼働中** |
| X（後追い） | ドメインを絞った WebSearch。投稿本文と正確な投稿日時が取れるが、**最新でも 41 日前**（実測） | **稼働中** |
| X（キーワード検索） | API / Yahoo!リアルタイム検索 / アカウント購読。実装済みだが全経路が遮断中 | 要許可 |
| RSS（ニュース） | ナタリー3系統、アニメ！アニメ！、映画.com、アニメイトタイムズ、リスアニ！、MOVIE WALKER、電撃ホビー、アキバ総研、ファミ通、アニメハック、PR TIMES | 遮断中 |
| YouTube | 公式チャンネルの Atom フィード（認証不要）。予告公開が告知より早いことがある | 遮断中 |
| 劇場サイト | 新文芸坐・塚口サンサン劇場・早稲田松竹・目黒シネマ・シネマート新宿・シネマスコーレ | 遮断中 |
| 記事本文 | 日付の裏取りと年の訂正に使う | 遮断中 |

「遮断中」は、この環境の egress ポリシーが許可制で、対象ドメインが
許可されていないため。コードは用意してあるので、許可が下りれば動く。
何に届くかは `python3 -m aew.preflight` で確認できる。

### X（Twitter）

**現状は後追いしかできていない。** ドメインを x.com に絞った WebSearch は
動くが、速報性が無い。2026-09-20 に「リバイバル上映 決定 アニメ」で実測
したところ、返ってきた投稿は次のとおりだった。

| | 経過 |
|---|---|
| 最新の投稿 | **41 日前** |
| 中央値 | 120 日前 |
| 最古 | 549 日前 |

検索エンジンの索引を経由する以上これは避けられない。チケットの発売告知
には間に合わないので、**X は現状「取りこぼしを拾う」用途**と考えるべき。

日付の扱いだけは X が最も強い。status URL の ID は投稿時刻を埋め込んだ
snowflake なので、**ID から投稿日時を厳密に復元できる**（`aew/xposts.py`）。
古い投稿を新しい予定と誤認する事故は、これで構造的に防げている。

#### 本物のキーワード検索を通すには

`aew/xsearch.py` に 3 つの経路を実装済み。**いずれも egress ポリシーで
塞がれており、許可が下りるまで動かない。** 許可されれば自動的に切り替わる。

| 経路 | 許可が要るホスト | 費用 | できること |
|---|---|---|---|
| X API v2 | `api.x.com` | 有料枠 + `X_BEARER_TOKEN` | 直近 7 日をキーワード検索。最も正確で速い |
| Yahoo!リアルタイム検索 | `search.yahoo.co.jp` | 無料 | X を実時間で索引。日本語に強い。**費用対効果が最も高い** |
| 公式アカウント購読 | `syndication.twitter.com` | 無料 | 指定アカウントの最近の投稿。キーワード検索は不可 |

**API キーを買うだけでは解決しない。** `api.x.com` 自体が 403 で塞がれて
いるため、トークンがあっても呼べない。ネットワーク許可が先。

到達状況は `python3 -m aew.preflight` で確認できる。

## 収集経路が 2 つある理由

**WebSearch 経路（現在こちらで稼働）** — セッションが検索を実行し、
結果を候補として流し込む。追加設定なしで動く。
反面、検索インデックス経由なので数日のタイムラグがあり、
記事本文が読めないぶん日程を取り逃すことがある。

**RSS 経路（`aew/collect_rss.py`、現在は不通）** — 各社のフィードを直接読む。
速報性と精度は上だが、この環境の egress ポリシーが
natalie.mu / animeanime.jp / eiga.com などを 403 で塞いでいるため、
現状では全フィードが失敗する。

許可を広げるには、[Claude Code on the web の環境設定](https://code.claude.com/docs/en/claude-code-on-the-web)
でネットワークポリシーを変更し、`aew/sources.py` に挙げたドメインを通す。
変更後は `python3 -m aew.preflight` で到達できるようになったか確認する。
許可が下りたら、手順 3 の WebSearch を

```bash
python3 -m aew.collect_rss --out /tmp/candidates.json
```

に差し替えるだけでよい。出力形式は揃えてある。

## 手で動かす

```bash
python3 -m aew.sources --watchlist watchlist.json      # 検索クエリを見る
python3 -m aew.ingest --candidates candidates.json     # --commit なしなら state を汚さない
python3 -m unittest discover -s tests -t .             # テスト
```

`--commit` を付けるまで `state/seen.json` は更新されない。
結果を確認してから記録する運用ができる。
